# ON (OppaNavi)

자전거 라이더를 위한 오프라인 네비게이션 플랫폼

---

# 프로젝트 목적

ON은 단순한 네비게이션 앱이 아니다.

사용자가 실제 라이딩 중 필요로 하는 기능을 하나의 플랫폼 안에 통합하는 것을 목표로 한다.

핵심 철학은 다음과 같다.

* 오프라인 우선
* 라이더 중심
* 불필요한 복잡성 최소화
* 실주행 검증 기반 개발
* 기능보다 안정성 우선

# 현재 개발 상태

## 구현 완료

### GPS Tracking
* GPS 위치 수집
* 주행 기록

* GPX 파일 로드
* 경로 표시
* 현재 위치 추적
* 경로 이탈 감지

### Ride Logging
* CSV 기반 로그 저장
* 주행 데이터 기록 (19개 컬럼)
* 이벤트 상태 로그 포함

* CameraX 기반
* PIP Preview
* 순환버퍼 녹화 (20초×3슬롯)
* 이벤트 4종 감지/녹화
* 블랙박스 기능
* 현재 상태: 검증/튜닝 단계

# 모듈 관계 원칙

모든 기능은 가능한 독립 모듈로 구성한다.

```

↓
GPS / GPX / 지도 / 주행기록 정상 동작

RouteModule 제거
↓
GPS / GPX / Camera 정상 동작
```

Core 기능과 부가기능은 분리 유지한다.

# 개발 원칙

## 1. 로그 우선
추측 금지.
모든 판단은 실주행 로그 기반.

## 2. 상수 집중 관리
매직 넘버 사용 금지.
```
예) BUFFER_DURATION / IMPACT_THRESHOLD_G
```
설정값은 파일 상단에 집중 관리.
추후 SharedPreferences 전환 가능한 구조 유지.

## 3. 실주행 검증
```
실내 테스트 통과
↓
실주행 검증
↓
적용
```
에뮬레이터보다 실주행 우선.

## 4. 기능보다 안정성
새 기능 추가보다 기존 기능 안정화 우선.

## 5. 단계별 개발
```
PoC
↓
기능 구현
↓
실주행 검증
↓
튜닝
↓
정식 적용
```

# 테스트 철학

실패한 테스트도 성공이다.
목적은 통과가 아니라 문제 발견이다.

최악의 상황을 의도적으로 만든다.
```
이벤트 폭탄
강제 종료
장시간 사용 (목표: 땡볕 6시간)
GPS 이탈
발열 환경
```

문제가 발견되면:
```
수정 → 재현 → 검증
```

# 장기 비전

ON은 단순한 GPX 플레이어가 아니다.

최종적으로는:
* 네비게이션
* 블랙박스
* 라이딩 기록
* 오프라인 경로 탐색

을 통합한 라이더 플랫폼을 목표로 한다.

기능은 계속 늘어날 수 있지만 항상 다음 원칙을 유지한다.

```
"Core는 가볍고 안정적으로,
확장 기능은 독립적으로."
```
